# Shared normative point model (Refs #121, #447)

This standalone phase does **not** replace UI or native-codec time paths yet.
The payload is derived directly from verified Global-TZ2026egtz-rearguard TZif
and complete POSIX future rules. ThreeTenBP ZoneRules are not its source: their
blocking historical/future provider defect is recorded separately under
[diagnostics/](diagnostics/BP-PROVIDER-BLOCKER.md).

[provenance.json](provenance.json) binds the exact signed upstream tag, official
release asset digest, generated bytes, version, and retained public-domain license.
Global-TZ history deliberately differs from normal IANA history; a historical
reference must use this exact source variant. No JAR checksum or upstream source
was changed. No issue was opened in an upstream repository.

## Model v2

`zones` maps every original accepted Zone/Link name to a deduplicated record.
There are 597 names, including all 592 previous BP-registry names and five additional
UTC/GMT aliases;158 names share complete data. No source TZID is renamed.
`Factory` explicitly denotes unknown local time and is rejected rather than guessed
as UTC. Normal fixed `UT` and `Z` UTC spellings are also accepted by the API.

Each `rules` record is:

```
[initialTypeIndex,
 types[[offsetSeconds, isDST, abbreviation, standardIndicator, utcIndicator]],
 historyFlat[UTCepochSeconds, typeIndex, ...],
 tail[standardOffset, standardName, dstOffsetOrNull, dstNameOrNull,
      startRuleOrNull, endRuleOrNull, originalPOSIX]]
```

A future date rule is `[kind,a,b,c,signedClockSeconds]`:

- `M`: month1..12, week1..5 (5 means last), weekday0..6 (Sunday0).
- `J`: day1..365 excluding February29; `b=c=0`.
- `N`: ordinal day0..365 including February29; `b=c=0`.

Clocks support signed hours through167:59:59. Crossing a day, month or year is
intentional. POSIX transition clocks are wall clocks: DST entry subtracts the
standard offset, and exit subtracts the DST offset. Original UTC/STANDARD/WALL
source rules are already normalized by TZif/zic into UTC history and POSIX wall
rules; the resolver never guesses a time-definition suffix. Missing/unknown
footers, implementation-defined implicit DST rules, unknown suffixes, malformed
bounds and leap-second axes fail closed. A known constant POSIX tail is an
explicit unlimited constant rule, not an inference from finite history.

`resolver.js` exports a factory (CommonJS or `MagnolieTimezoneProvider`) with:

```
provider.offsetAt(identifier, epochMilliseconds) -> integer offsetSeconds
provider.wallParts(identifier, epochMilliseconds)
  -> {year,month,day,hour,minute,second,millisecond,offsetSeconds}
provider.resolveWall(identifier, civilParts, {gap,fold}) -> epochMilliseconds|null
```

`gap` is `reject` (default), `forward` (use the before-gap offset) or `omit`.
`fold` is `earlier` (default), `later` or `reject`. Invalid/unknown input throws a
coded RangeError. Fold candidates are exact, not sampled. Last rules apply only
after the final history timestamp and are evaluated around the requested year;
there is no finite future table, occurrence expansion, global Intl override,
async bridge or mutable caller-owned rule storage. Public wall years1..9999 also
support instants crossing the adjacent UTC-year boundary. Existing embedded
source VTIMEZONE must retain priority in future integration.

## Reproduce

Use the official archive URL/hash in provenance.json. No download or execution
of an unverified artifact occurs in these scripts:

```sh
python3 port-adapters/timezones/build-tzif.py GLOBAL_TZ_ARCHIVE
python3 port-adapters/timezones/build-tzif.test.py
node port-adapters/timezones/resolver.test.cjs
python3 port-adapters/timezones/check-independent.py GLOBAL_TZ_ARCHIVE
```

Only `build-tzif.py ... --write` deliberately regenerates the JSON. The default
checks exact generated bytes. `zic -b fat` is a host build tool, not a runtime
dependency; a different output fails the committed-byte comparison.
The independent reference uses CPython ZoneInfo to parse the exact compiled TZif,
with its own POSIX implementation. All597 accepted source names receive year
1/99/400/2400/9999 point and wall checks. Every independent TZif transition receives
before/at/after checks and its real gap/fold midpoint. Every distinct POSIX footer
receives 400 Gregorian years of exact transition tests, plus year9999; fixed
footers have no fictitious transitions. This is an offline test, not data shipped
as a finite future approximation. Synthetic cases cover J/N/M, leap years,
signed clocks, end-of-day, time-definition normalization, alias equality,
predecessor/final history and malformed inputs.

The final standalone reference records 269,817 comparisons,40,521 TZif transition
timestamps and 24,060 future transitions across 93 distinct POSIX models, with zero
differences. The older blocked BP and first JS-prototype reports are separate.

The payload is 428,473bytes (gzip 95,067). One Node 24 diagnostic measured JSON parse
1.46ms, provider construction10.91ms and approximately 1.88MB retained provider heap.
These are host measurements, **not** Android/WebKit startup or memory acceptance.
Existing native startup/time limits must remain unchanged during integration.

Aggregate preflight occurs before large rule/registry/history copies: at most 2048
registry names,1024 records,8192 types,100000 historical transitions and 1Mi codeunits
of strings; names/abbreviations are at most 64characters, TZIDs 255, footers 512,
and the explicit rejection registry at most 16 entries with 128character reasons.
Negative tests prove rejection before the copy call. These bounds complement the
pinned real-asset SHA; they do not authorize arbitrary mutated databases.
