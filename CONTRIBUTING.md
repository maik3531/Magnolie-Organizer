# Contributing / Mitwirken

## English

Thank you for helping Magnolie. Bug reports, translations, documentation fixes
and focused code improvements are welcome.

1. Search existing issues before opening a new one.
2. State the affected component, platform and version.
3. Describe how to reproduce a bug and what you expected instead.
4. Keep pull requests focused on one component and one concern.
5. Run the tests documented in that component's `LIESMICH.md`.
6. Never commit personal data, signing material, credentials or generated packages.

Every change must reference an existing or new GitHub issue with a clear goal
and verifiable completion criteria. Finish one scoped task before starting
another; record newly discovered work separately. Link commits and pull requests
to the issue. Use `Refs #N` for partial progress and `Closes #N` only when its
completion criteria are met. Record the actual result and remaining work in the
issue. A development snapshot is not a release.

Make product changes in this repository, never in temporary build copies,
extracted packages or test machines. See [AGENTS.md](AGENTS.md) for the working
rules and [issue #4](https://github.com/maik3531/Magnolie-Organizer/issues/4) for
the current 2.0.19 work list.

For a security vulnerability, do not open a public issue. Follow
[SECURITY.md](SECURITY.md) instead.

## Deutsch

Danke für deine Unterstützung. Fehlerberichte, Übersetzungen,
Dokumentationskorrekturen und klar abgegrenzte Codeverbesserungen sind willkommen.

1. Vor einem neuen Issue bitte nach bestehenden Meldungen suchen.
2. Betroffenen Bestandteil, Plattform und Version nennen.
3. Bei Fehlern die Schritte zum Nachstellen und das erwartete Verhalten beschreiben.
4. Pull Requests auf einen Bestandteil und ein Anliegen begrenzen.
5. Die im jeweiligen `LIESMICH.md` beschriebenen Prüfungen ausführen.
6. Niemals persönliche Daten, Signiermaterial, Zugangsdaten oder erzeugte Pakete einchecken.

Jede Änderung benötigt ein vorhandenes oder neues GitHub-Issue mit klarem Ziel
und überprüfbaren Abschlusskriterien. Eine abgegrenzte Aufgabe abschließen,
bevor die nächste begonnen wird; neue Befunde getrennt erfassen. Commits und
Pull Requests mit dem Issue verknüpfen. `Refs #N` bezeichnet einen Zwischenstand,
`Closes #N` nur vollständig erfüllte Abschlusskriterien. Tatsächliches Ergebnis
und offene Arbeit im Issue festhalten. Ein Entwicklungsstand ist kein Release.

Produktänderungen erfolgen in diesem Repository, nicht in temporären Baukopien,
entpackten Paketen oder Testsystemen. Die Arbeitsregeln stehen in
[AGENTS.md](AGENTS.md), die aktuelle Aufgabenliste für 2.0.19 in
[Issue #4](https://github.com/maik3531/Magnolie-Organizer/issues/4).

Sicherheitslücken bitte nicht öffentlich melden, sondern nach
[SECURITY.md](SECURITY.md) vorgehen.
